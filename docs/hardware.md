# 하드웨어 설계

PocketBeagle 2로 HUB75 LED 매트릭스를 구동해 30fps 영상까지 출력하는 것이 목표다.
이 문서는 해상도 선정 근거, 부품 목록, 전원 설계, 배선을 다룬다.

## 1. 최대 해상도 분석

### 제약 조건

HUB75 패널은 자체 프레임버퍼가 없다. 컨트롤러(PocketBeagle 2)가 **쉬지 않고**
행 데이터를 시프트하며 스캔해야 하고, 색 심도는 BCM(Binary Code Modulation)으로
같은 프레임을 비트플레인별로 여러 번 뿌려서 만든다. 따라서 한계는 세 가지다.

1. **시프트 클럭 속도** — PocketBeagle 2(TI AM6232)의 PRU 코어로 비트뱅잉할 때
   실용적인 HUB75 클럭은 보수적으로 **약 15~20 MHz**로 잡는다.
2. **리프레시율** — 눈으로 깜빡임이 안 보이고 카메라에 줄이 덜 생기려면
   **최소 120 Hz, 권장 200 Hz 이상**.
3. **영상 디코딩** — AM6232의 듀얼 Cortex-A53(최대 1.4 GHz)로 ffmpeg 소프트웨어
   디코딩. 원본을 매트릭스 해상도로 다운스케일하므로 720p 소스 → 128×64 @30fps는 여유 있다.
   병목은 디코딩이 아니라 매트릭스 갱신 쪽이다.

### 대역폭 계산

1/32 스캔 64×64 패널을 C장 체인(가로 W = 64·C, 세로 64), 색 심도 N비트/채널일 때
한 리프레시에 필요한 시프트 클럭 수:

```
클럭 수 = W × 32(행쌍) × N(비트플레인)
리프레시율 ≈ 클럭 속도 / 클럭 수   (시프트 제한 근사)
```

클럭 20 MHz 기준:

| 구성 | W×H | N (비트/채널) | 클럭 수/리프레시 | 이론 리프레시율 | 판정 |
|---|---|---|---|---|---|
| 64×64 ×1 | 64×64 | 8 | 16,384 | ~1.2 kHz | 여유 |
| 64×64 ×2 | **128×64** | 8 | 32,768 | **~600 Hz** | **권장** |
| 64×64 ×3 | 192×64 | 8 | 49,152 | ~400 Hz | 가능 |
| 64×64 ×4 | 256×64 | 8 | 65,536 | ~300 Hz | 가능 (상한선) |
| 64×64 ×6 | 384×64 | 7 | 86,016 | ~230 Hz | 색 심도 타협 |

실제로는 BCM 표시 시간·LAT/주소 전환 오버헤드로 이론값의 절반 정도로 보는 게 안전하다.
그래도 **단일 체인으로 256×64까지는 8비트 색으로 120 Hz 이상**을 지킬 수 있다.

### 결론: 권장 설계

- **기본(이 리포의 기본 설정): 128×64 — 64×64 P3 패널 2장 체인.**
  리프레시 여유가 커서 밝기·색 품질이 좋고, 영상(16:9를 2:1로 크롭/패드)도 볼만하다.
- **확장: 256×64 (4장 체인)** — 소프트웨어 변경 없이 `MATRIX_WIDTH=256`으로 확장 가능한 상한.
- **스트레치 골: 256×128 (2체인 병렬 × 4장)** — PRU가 데이터 6핀 × 2체인 = 12핀을
  동시에 구동해야 한다. PocketBeagle 2 헤더에 나온 PRU 고속 출력 핀 수를 확인한 뒤에
  결정한다 (아래 §6 검증 항목).

> 픽셀 피치는 시청 거리로 고른다: P3(3mm)이면 128×64가 384×192mm — 책상 위 1~2m 시청에 적당.
> 더 크게 보려면 P4/P5.

## 3. 전원 설계

- **LED 전원과 로직 전원 분리**: 패널 5V는 파워서플라이에서 **각 패널로 직접** 배선한다
  (체인 커넥터로 전원을 넘기지 말 것 — 전압 강하로 색이 틀어진다).
- PocketBeagle 2는 별도 5V(USB)로 급전하되 **GND는 반드시 패널 전원과 공통**으로 묶는다.
- 각 패널 전원 입력에 1000µF 벌크 커패시터. 스캔 전환 시 전류 스파이크 흡수용.
- 전선 굵기: 패널당 4A 기준 18AWG 이상.

## 4. 신호 배선

HUB75(E) 커넥터 핀아웃 (2×8 IDC, 키홈이 왼쪽일 때):

```
 R1 ○ ○ G1
 B1 ○ ○ GND
 R2 ○ ○ G2
 B2 ○ ○ E
  A ○ ○ B
  C ○ ○ D
CLK ○ ○ LAT
 OE ○ ○ GND
```

필요 신호 14개: 데이터 6 (R1,G1,B1,R2,G2,B2) + 행 주소 5 (A~E, 1/32 스캔) + CLK, LAT, OE.

- **모든 신호는 74HCT245를 거쳐 5V로 레벨시프트**한다. PB2 GPIO는 3.3V라서
  패널에 따라 직결 시 마진이 없어 글리치가 생긴다. DIR=A→B, OE=GND 고정.
- CLK 라인은 가장 민감하다. 배선을 짧게 하고, 가능하면 22~33Ω 직렬 저항.
- 체인: 컨트롤러 → 패널1 IN, 패널1 OUT → 패널2 IN.

### PocketBeagle 2 핀 할당

14개 신호를 PRU에서 직접 토글할 수 있는 핀에 배치해야 한다. **AM6232의 PRUSS-M
핀이 PB2의 P1/P2 헤더 어디에 나와 있는지는 PocketBeagle 2 System Reference Manual과
`show-pins` 출력으로 확정한 뒤** 아래 표를 채운다 (§6 검증 항목 1).

| 신호 | PB2 핀 | 비고 |
|---|---|---|
| R1,G1,B1,R2,G2,B2 | TBD | PRU 출력 핀 필수 (고속) |
| CLK | TBD | PRU 출력 핀 필수 |
| LAT, OE | TBD | PRU 출력 권장 |
| A,B,C,D,E | TBD | 행 전환 시에만 바뀜 — 일반 GPIO도 가능 |

## 5. 확장: USB-A 2포트 + 이더넷(RJ45)

PocketBeagle 2에는 USB-A 호스트 포트와 이더넷이 기본 탑재되어 있지 않다.
온보드는 USB-C(전원 + 디바이스/호스트 겸용) 하나이고, 두 번째 USB(USB1)가
P1/P2 헤더에 D+/D− 신호로 나와 있다. 이 USB1을 업스트림으로 써서 확장한다.

### 옵션 A — 시판 부품으로 빠르게 (납땜 최소)

헤더의 USB1 D+/D−를 USB-A 리셉터클 브레이크아웃에 연결하고, 거기에
**이더넷 포함 USB 허브**(RJ45 + USB-A 포트가 있는 시판 허브)를 꽂는다.

- 장점: 바로 동작, 리눅스에서 표준 `usbnet`/허브 드라이버로 잡힘
- 단점: 케이블·어댑터가 지저분하고 케이스 설계가 어려움
- 프로토타입 단계에서 기능 검증용으로 추천

### 옵션 B — 확장 케이프 PCB (권장 최종 형태)

**Microchip LAN9512** 한 칩으로 요구사항이 정확히 해결된다:
USB 2.0 허브 + **다운스트림 USB 2포트** + **10/100 이더넷**을 통합한 칩으로,
초기 라즈베리파이 모델 B와 같은 구성이다. (USB 4포트가 필요해지면 LAN9514.)

```
PB2 헤더 USB1 (D+/D−) ──► LAN9512 ──┬─► USB-A ×2 (VBUS 스위치 경유)
                                    └─► RJ45 magjack (10/100)
```

주변 부품:

| 부품 | 수량 | 비고 |
|---|---|---|
| LAN9512 (또는 LAN9514) | 1 | 재고/단종 여부 확인. 대안: USB2512 허브 + LAN9500A 조합 |
| 25 MHz 크리스탈 + 부하 커패시터 | 1 | LAN9512 클럭 |
| RJ45 magjack (마그네틱 내장, 예: HR911105A) | 1 | LED 포함 권장 |
| USB-A 리셉터클 | 2 | |
| VBUS 전원 스위치 (TPS2051 등) 또는 폴리퓨즈 500mA | 2 | 포트당 과전류 보호 |
| USB/이더넷 ESD 보호 (TPD4S012 등) | 2~3 | 커넥터 노출 라인 전부 |
| 3.3V 레귤레이터 | 1 | LAN9512 공급 (1.8V는 칩 내장 레귤레이터 사용) |

- USB D+/D−는 90Ω 차동 임피던스로 짧게 배선하고 길이를 맞춘다.
- 이더넷 MDI 라인은 100Ω 차동, magjack까지 최단 거리.

### 옵션 C — 네이티브 이더넷 (조건부 최고 성능)

AM6232에는 기가비트 이더넷 MAC(CPSW)이 내장되어 있어, 외부 **RMII PHY**
(LAN8720 등)만 붙이면 USB 대역폭을 쓰지 않는 네이티브 10/100 이더넷이 된다.
단, **RMII 신호가 PB2 헤더에 나와 있는지, HUB75가 쓸 핀과 겹치지 않는지**
확인이 선행되어야 한다 (§6 검증 항목). 겹치면 옵션 B로 간다.

### 전원 예산 재계산

| 소비처 | 최대 전류 (5V) |
|---|---|
| 64×64 패널 ×2 (전체 흰색) | ~8 A |
| PocketBeagle 2 본체 | ~0.7 A |
| USB-A ×2 (포트당 500mA) | 1.0 A |
| 허브/이더넷 칩 | ~0.3 A |
| **합계** | **~10 A** |

USB 확장까지 하면 5V 10A가 딱 맞아떨어지므로 **12A급으로 상향**하거나,
USB 확장 보드에 별도 5V 입력을 두는 것을 권장한다. (실사용 콘텐츠에서
패널이 최대 전류를 다 쓰는 일은 드물지만 여유는 필수.)

## 6. 검증해야 할 항목 (진행하면서 채움)

1. [ ] PB2 헤더에 노출된 PRUSS-M 고속 출력 핀 개수/위치 확인 → 핀 할당표 확정
2. [ ] PRU 비트뱅잉 실측 최대 클럭 측정 (로직 애널라이저)
3. [ ] 구매한 패널의 스캔 방식(1/32) 및 드라이버 IC 확인 — ICN2037 등 일반형이면 무관,
      FM6126A류는 초기화 시퀀스 필요
4. [ ] 2체인 병렬(256×128 스트레치 골) 핀 여유 확인
5. [ ] 실제 리프레시율/밝기에서 카메라 플리커 확인
6. [ ] USB1 D+/D−가 나오는 P1/P2 헤더 핀 위치 확인 (SRM) + 호스트 모드 활성화 확인
7. [ ] LAN9512 수급 확인 (단종/재고) — 불가 시 USB2512+LAN9500A 또는 옵션 A로
8. [ ] AM6232 RMII 신호의 헤더 노출 여부 확인 (옵션 C 가능성 판단)

## 7. 소프트웨어와의 접점

백엔드 드라이버(`backend/app/driver/hub75_pru.py`)는 렌더링된 프레임(W×H×3, RGB888)을
공유 메모리에 쓰고, PRU 펌웨어가 이를 BCM 비트플레인으로 변환해 패널로 뿌린다.
펌웨어 설계는 [../pru/README.md](../pru/README.md) 참고.
