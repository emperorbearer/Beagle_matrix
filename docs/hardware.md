# 하드웨어 설계

HUB75 LED 매트릭스에 30fps 영상까지 출력하는 것이 목표다. 웹앱(프론트엔드 + 서버)은
공통이고, 구동 하드웨어는 **라즈베리파이 4** 또는 **PocketBeagle 2** 중에서 고를 수 있다
(`MATRIX_DRIVER` 환경변수로 선택, §5).

## 1. 플랫폼 선택

| | 경로 A: Raspberry Pi 4 + rpi-rgb-led-matrix | 경로 B: PocketBeagle 2 + PRU |
|---|---|---|
| 최대 해상도 | 병렬 3체인, **256×192급 실증됨** | 이론상 256×128 (2체인), 미검증 |
| 소프트웨어 | hzeller 라이브러리 완성품, 바로 사용 | PRU 펌웨어 직접 개발 필요 |
| 타이밍 품질 | CPU 코어 점유 방식, 튜닝(isolcpus)으로 실용상 충분 | PRU 전용 코어라 지터 제로 (구조상 우월) |
| USB-A / 이더넷 | 기본 내장 | 확장 케이프 설계 필요 (§4.5) |
| 가격 / 전력 | 조금 비쌈, 전력 큼 | 저렴, 저전력 |
| 완성까지 걸리는 시간 | 며칠 | 몇 주~몇 달 (펌웨어 개발) |

- **빨리, 크게, 안정적으로** → 경로 A (라즈베리파이 4). ⚠️ **라즈베리파이 5는 불가**
  (RP1 GPIO 미지원). Pi 4 또는 소형 구성이면 Zero 2 W.
- **PRU 펌웨어 개발 자체가 목적/재미** → 경로 B.

두 경로 모두 웹앱 코드는 동일하다. 드라이버만 갈아 끼운다.

## 2. 공통 배경: HUB75 구동 제약

HUB75 패널은 자체 프레임버퍼가 없다. 컨트롤러가 **쉬지 않고** 행 데이터를 시프트하며
스캔해야 하고, 색 심도는 BCM(Binary Code Modulation)으로 같은 프레임을 비트플레인별로
여러 번 뿌려서 만든다. 그래서 한계는:

1. **시프트 클럭 × 병렬 체인 수** = 총 대역폭 → 해상도 상한
2. **리프레시율** — 깜빡임이 안 보이려면 최소 120 Hz, 권장 200 Hz 이상
3. **영상 디코딩** — 원본을 매트릭스 해상도로 다운스케일하므로 CPU 부담은 작다.
   병목은 디코딩이 아니라 매트릭스 갱신 쪽.

공통 전원 원칙 (플랫폼 무관):

- LED 전원은 파워서플라이에서 **각 패널로 직접** 배선 (체인 커넥터로 전원을 넘기지 말 것).
- 컨트롤러 보드는 별도 5V로 급전하되 **GND는 패널 전원과 공통**.
- 각 패널 전원 입력에 1000µF 벌크 커패시터. 전선은 패널당 4A 기준 18AWG 이상.
- 64×64 패널 1장 최대 전류 ~4A(전체 흰색). 패널 수 × 4A + 보드 ~1A로 PSU 용량 산정.

## 3. 경로 A — 라즈베리파이 4 + rpi-rgb-led-matrix

[hzeller/rpi-rgb-led-matrix](https://github.com/hzeller/rpi-rgb-led-matrix)는 10년 이상
다듬어진 사실상 표준 라이브러리다. FM6126A 초기화, 디더링, 밝기 보정 내장.

### 3.1 부품 목록 (BOM)

| # | 부품 | 수량 | 비고 |
|---|---|---|---|
| 1 | Raspberry Pi 4 (2GB+) | 1 | **Pi 5 불가.** 소형 구성은 Zero 2 W |
| 2 | 64×64 HUB75 패널, 1/32 스캔, P3 | 2~12 | 구성은 §3.2 |
| 3 | 어댑터 보드 | 1 | 아래 중 택 1 |
| 4 | 5V 파워서플라이 | 1 | 패널 수 × 4A + 여유 (예: 6장 → 30A급) |
| 5 | 16핀 IDC 케이블, 전원 케이블 | n | |
| 6 | 전해 커패시터 1000µF | 패널당 1 | |

어댑터 보드 (GPIO 직결 대신 반드시 사용 — 레벨시프트 내장):

- **Adafruit RGB Matrix Bonnet/HAT** — 1체인 전용. 쉽고 문서 좋음. 128×64급까지.
- **Active-3 계열 (Electrodragon RGB LED Matrix Panel Drive Board 등)** — **병렬 3체인**.
  최대 해상도용. 이 프로젝트의 권장 보드.

### 3.2 해상도 가이드

| 구성 | 어댑터 | 해상도 | 비고 |
|---|---|---|---|
| 1체인 × 2장 | Bonnet 가능 | 128×64 | 기본 목표. 리프레시 여유 큼 |
| 1체인 × 4장 | Bonnet 가능 | 256×64 | 무난 |
| 3체인 × 각 2장 | Active-3 | 128×192 또는 256×96 | |
| 3체인 × 각 4장 | Active-3 | **256×192** | 실증된 상한급. `pwm_bits` 조정으로 리프레시 확보 |

체인이 길어질수록 리프레시가 떨어진다. 큰 구성에서는 `RPI_PWM_BITS`를 11 → 8~9로
낮추면 리프레시가 올라간다 (색 계조와 트레이드오프).

### 3.3 시스템 설정 (중요)

```bash
# 1) 온보드 사운드 비활성화 — PWM 하드웨어 충돌
#    /boot/firmware/config.txt 에 추가:
dtparam=audio=off

# 2) CPU 코어 격리 — 스캔 전용 코어 확보로 플리커 억제
#    /boot/firmware/cmdline.txt 끝에 추가:
isolcpus=3

# 3) 라이브러리 + 파이썬 바인딩 빌드
sudo apt install -y python3-dev cython3
git clone https://github.com/hzeller/rpi-rgb-led-matrix
cd rpi-rgb-led-matrix
make build-python PYTHON=$(which python3)
sudo make install-python PYTHON=$(which python3)
```

### 3.4 웹앱 연결

```bash
MATRIX_DRIVER=rpi MATRIX_WIDTH=128 MATRIX_HEIGHT=64 \
  sudo -E .venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 80
```

- GPIO 접근 때문에 root 필요 (라이브러리가 초기화 후 권한을 스스로 내려놓는다).
- 어댑터가 Adafruit 계열이면 `RPI_HARDWARE_MAPPING=adafruit-hat` (또는 점퍼 개조 시
  `adafruit-hat-pwm`), Active-3 계열이면 기본값 `regular`.
- Pi 4에서 깜빡이면 `RPI_GPIO_SLOWDOWN`을 4→5로.

## 4. 경로 B — PocketBeagle 2 + PRU (자작 펌웨어)

### 4.1 최대 해상도 분석

PocketBeagle 2(TI AM6232)의 PRU(PRUSS-M, 333MHz)로 비트뱅잉한다. PRU의 R30 레지스터는
한 인스트럭션에 최대 16핀을 동시 구동하므로 (R31은 입력 전용) **단일 코어로 2체인**
(데이터 12 + CLK/LAT/OE 3 = 15핀)까지 가능하다. 클럭을 보수적으로 20MHz로 잡으면:

| 구성 | W×H | N (비트/채널) | 클럭 수/리프레시 | 이론 리프레시율 | 판정 |
|---|---|---|---|---|---|
| 64×64 ×2 | **128×64** | 8 | 32,768 | **~600 Hz** | **권장 시작점** |
| 64×64 ×4 | 256×64 | 8 | 65,536 | ~300 Hz | 단일 체인 상한 |
| 2체인 × 각 4장 | 256×128 | 8 | 65,536/체인 | ~300 Hz | 스트레치 골 (핀 확인 필요) |

실제로는 BCM 표시 시간·오버헤드로 이론값의 절반 정도로 보는 게 안전하다.
PRU 코어 2개를 동기화하면 산술상 4체인(256×256급)까지 가능하지만, 헤더에 노출된
PRU GPO 핀 수 확인이 선행되어야 한다 (§4.6 검증 항목 1).

> 픽셀 피치는 시청 거리로 고른다: P3(3mm)이면 128×64가 384×192mm — 책상 위 1~2m 시청에 적당.

### 4.2 부품 목록 (BOM) — 128×64 기준

| # | 부품 | 수량 | 비고 |
|---|---|---|---|
| 1 | PocketBeagle 2 | 1 | TI AM6232, 512MB RAM |
| 2 | 64×64 HUB75 패널, 1/32 스캔, P3 | 2 | 구매 시 "HUB75E"(E 주소선 포함) 확인 |
| 3 | 5V 파워서플라이 ≥10A | 1 | USB/이더넷 확장 시 12A 권장 (§4.5) |
| 4 | 74HCT245 (레벨시프터) | 2 | 3.3V→5V, 8ch × 2 = 14신호 커버. **HCT** 필수 |
| 5 | 16핀 IDC 케이블 (2×8) | 2 | 패널 간 체인 + 컨트롤러→패널 |
| 6 | 전원 케이블 (패널 부속) | 2 | 각 패널에 5V 직접 인젝션 |
| 7 | 전해 커패시터 1000µF/6.3V+ | 2 | 각 패널 전원 입력단 |
| 8 | microSD, 5V→PB2 전원(USB) | 1식 | |
| 9 | (선택) 프로토보드 또는 어댑터 PCB | 1 | 레벨시프터 + 커넥터 정리용 |
| 10 | USB-A ×2 + 이더넷 확장 부품 | 1식 | §4.5 참고 |

### 4.3 신호 배선

HUB75(E) 커넥터 핀아웃 (2×8 IDC, 키홈이 왼쪽일 때):

```
 R1 ○ ○ G1
 B1 ○ ○ GND
 R2 ○ ○ G2
 B2 ○ ○ E
  A ○ ○ B
  C ○ ○ D
CLK ○ ○ LAT
 OE ○ ○ GND
```

필요 신호 14개: 데이터 6 (R1,G1,B1,R2,G2,B2) + 행 주소 5 (A~E, 1/32 스캔) + CLK, LAT, OE.

- **모든 신호는 74HCT245를 거쳐 5V로 레벨시프트**한다. PB2 GPIO는 3.3V라서
  패널에 따라 직결 시 마진이 없어 글리치가 생긴다. DIR=A→B, OE=GND 고정.
- CLK 라인은 가장 민감하다. 배선을 짧게 하고, 가능하면 22~33Ω 직렬 저항.
- 체인: 컨트롤러 → 패널1 IN, 패널1 OUT → 패널2 IN.

핀 할당: 14개 신호를 PRU R30으로 토글할 수 있는 핀에 배치해야 한다. **AM6232의
PRUSS-M 핀이 PB2의 P1/P2 헤더 어디에 나와 있는지는 System Reference Manual과
`show-pins` 출력으로 확정한 뒤** 채운다 (§4.6 검증 항목 1).

| 신호 | PB2 핀 | 비고 |
|---|---|---|
| R1,G1,B1,R2,G2,B2 | TBD | PRU R30 출력 핀 필수 (고속) |
| CLK | TBD | PRU R30 출력 핀 필수 |
| LAT, OE | TBD | PRU 출력 권장 |
| A,B,C,D,E | TBD | 행 전환 시에만 바뀜 — 일반 GPIO도 가능 |

### 4.4 전원 예산

| 소비처 | 최대 전류 (5V) |
|---|---|
| 64×64 패널 ×2 (전체 흰색) | ~8 A |
| PocketBeagle 2 본체 | ~0.7 A |
| USB-A ×2 (포트당 500mA) | 1.0 A |
| 허브/이더넷 칩 | ~0.3 A |
| **합계** | **~10 A** |

USB 확장까지 하면 10A가 딱 맞아떨어지므로 **12A급으로 상향**하거나 USB 확장 보드에
별도 5V 입력을 두는 것을 권장한다.

### 4.5 확장: USB-A 2포트 + 이더넷(RJ45)

(라즈베리파이 경로에서는 기본 내장이라 이 절이 필요 없다.)

PocketBeagle 2에는 USB-A 호스트 포트와 이더넷이 없다. 온보드는 USB-C(전원 +
디바이스/호스트 겸용) 하나이고, 두 번째 USB(USB1)가 P1/P2 헤더에 D+/D− 신호로
나와 있다. 이 USB1을 업스트림으로 써서 확장한다.

**옵션 A — 시판 부품으로 빠르게 (납땜 최소)**: 헤더의 USB1 D+/D−를 USB-A 리셉터클
브레이크아웃에 연결하고, 거기에 이더넷 포함 USB 허브를 꽂는다. 프로토타입 검증용.

**옵션 B — 확장 케이프 PCB (권장 최종 형태)**: **Microchip LAN9512** 한 칩으로
USB 2.0 허브 + 다운스트림 USB 2포트 + 10/100 이더넷이 해결된다 (초기 라즈베리파이
모델 B와 같은 구성. 4포트 필요 시 LAN9514).

```
PB2 헤더 USB1 (D+/D−) ──► LAN9512 ──┬─► USB-A ×2 (VBUS 스위치 경유)
                                    └─► RJ45 magjack (10/100)
```

| 부품 | 수량 | 비고 |
|---|---|---|
| LAN9512 (또는 LAN9514) | 1 | 재고/단종 확인. 대안: USB2512 허브 + LAN9500A |
| 25 MHz 크리스탈 + 부하 커패시터 | 1 | |
| RJ45 magjack (예: HR911105A) | 1 | LED 포함 권장 |
| USB-A 리셉터클 | 2 | |
| VBUS 스위치 (TPS2051 등) 또는 폴리퓨즈 500mA | 2 | 포트당 과전류 보호 |
| USB/이더넷 ESD 보호 (TPD4S012 등) | 2~3 | |
| 3.3V 레귤레이터 | 1 | 1.8V는 칩 내장 레귤레이터 |

USB D+/D−는 90Ω 차동 임피던스로 짧게, 이더넷 MDI는 100Ω 차동으로 magjack까지 최단 거리.

**옵션 C — 네이티브 이더넷**: AM6232 내장 기가비트 MAC(CPSW)에 외부 RMII PHY(LAN8720)를
붙이면 USB 대역폭을 안 쓰는 네이티브 이더넷이 된다. 단 RMII 신호의 헤더 노출 여부와
HUB75 핀 충돌 확인이 선행 (§4.6). 겹치면 옵션 B로.

### 4.6 검증해야 할 항목 (진행하면서 채움)

1. [ ] PB2 헤더에 노출된 PRUSS-M R30 출력 핀 개수/위치 확인 → 핀 할당표 확정
2. [ ] PRU 비트뱅잉 실측 최대 클럭 측정 (로직 애널라이저)
3. [ ] 구매한 패널의 스캔 방식(1/32) 및 드라이버 IC 확인 — ICN2037 등 일반형이면 무관,
      FM6126A류는 초기화 시퀀스 필요
4. [ ] 2체인 병렬(256×128 스트레치 골) 핀 여유 확인
5. [ ] 실제 리프레시율/밝기에서 카메라 플리커 확인
6. [ ] USB1 D+/D−가 나오는 P1/P2 헤더 핀 위치 확인 (SRM) + 호스트 모드 활성화 확인
7. [ ] LAN9512 수급 확인 (단종/재고) — 불가 시 USB2512+LAN9500A 또는 옵션 A로
8. [ ] AM6232 RMII 신호의 헤더 노출 여부 확인 (옵션 C 가능성 판단)

## 5. 소프트웨어와의 접점

드라이버는 `MATRIX_DRIVER` 환경변수로 선택한다:

| 값 | 대상 | 구현 |
|---|---|---|
| `sim` (기본) | 개발 PC, 하드웨어 없음 | 웹 미리보기가 곧 화면 |
| `rpi` | Raspberry Pi 4 + 어댑터 보드 | `backend/app/driver/rpi_hzeller.py` — rpi-rgb-led-matrix 바인딩 |
| `pb2` | PocketBeagle 2 + PRU | `backend/app/driver/hub75_pru.py` — 공유 메모리 프레임버퍼, 펌웨어는 [../pru/README.md](../pru/README.md) |

세 드라이버 모두 렌더링된 프레임(W×H×3, RGB888)을 받는 동일한 인터페이스
(`backend/app/driver/base.py`)를 구현한다. 프론트엔드·서버·렌더링 파이프라인은
플랫폼과 무관하게 공통이다.
