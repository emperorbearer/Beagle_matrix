# PRU 펌웨어 (개발 예정)

HUB75 스캔은 타이밍이 생명이라 리눅스 유저스페이스에서는 불가능하고,
PocketBeagle 2(AM6232)의 **PRUSS-M** 코어(2× PRU)에서 비트뱅잉한다.

## 설계

```
Linux (FastAPI 백엔드)                         PRU
┌─────────────────────┐    공유 DDR 메모리     ┌──────────────────────┐
│ hub75_pru.py         │ ┌────────────────┐   │ 1. 프레임버퍼 읽기      │
│  - RGB888 프레임 쓰기 │►│ 더블 버퍼        │──►│ 2. BCM 비트플레인 변환  │
│  - 버퍼 스왑 플래그    │ │ W×H×3 × 2      │   │ 3. 행 시프트+LAT+OE 스캔│
└─────────────────────┘ └────────────────┘   └──────────────────────┘
```

- **프레임버퍼**: remoteproc/rpmsg 또는 예약 메모리(carveout)에 더블 버퍼.
  리눅스 쪽은 프레임을 다 쓴 뒤 스왑 플래그만 올린다 (티어링 방지).
- **BCM 변환**: PRU가 RGB888 → 비트플레인 변환까지 맡을지, 리눅스 쪽에서
  미리 변환해 줄지는 PRU 성능 실측 후 결정 (리눅스 쪽 변환이 PRU 부담을 줄임).
- **스캔 루프**: 행쌍(1/32 스캔 = 32행쌍) × 비트플레인(8) 루프.
  플레인 k의 OE 시간은 2^k × T_base.

## 개발 순서

1. [ ] PRUSS-M 툴체인/예제 확인 (`ti-linux` PRU 지원, `/sys/class/remoteproc`)
2. [ ] LED 깜빡이기 수준의 PRU GPIO 토글 → 최대 토글 속도 실측
3. [ ] 단일 패널 64×64, 1비트 색으로 정적 이미지 스캔
4. [ ] BCM 8비트 색 심도 + 더블 버퍼 프레임 전달
5. [ ] 체인 2장(128×64) 검증, 리프레시율 측정
6. [ ] FM6126A 계열 패널 초기화 시퀀스 (해당 패널일 경우)
